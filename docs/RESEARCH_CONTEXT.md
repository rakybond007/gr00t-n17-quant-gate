# 이 연구가 무엇인가 — 처음 읽는 문서

VLA 정책을 **더 적은 스텝으로 같은 일을 하게** 만드는 연구다. 모델을 바꾸지도,
다시 학습시키지도 않는다. 추론 시점에 개입한다.

## 문제

GR00T-N1.5 같은 VLA 정책은 관측 하나를 받아 **16스텝짜리 행동 청크**를 내놓고,
로봇은 그것을 한 스텝씩 실행한다. 청크를 절반 속도로 실행하면(인접 두 스텝을 하나로)
스텝 수가 절반이 되지만, 아무 데서나 그렇게 하면 실패한다. 물건을 놓치거나, 좁은 곳에
넣다가 부딪히거나, 컨트롤러 한계를 넘어 변위가 잘려나간다.

핵심 주장은 하나다. **얼마나 압축하냐보다 어디를 압축하냐가 중요하다.**

RoboCasa Kitchen 의 OpenDrawer 에서 관측한 것:

```
무압축              성공률 0.72   성공시 229 스텝
무지성 K2 (전 구간)  성공률 0.44   성공시 136 스텝
게이트 기반 82% 압축 성공률 0.68   성공시 178 스텝
```

전 구간을 압축하면 성공률이 무너지는데, 압축할 구간을 골라내면 대부분을 지킨다.
그 "골라내는 것"이 **게이트**이고, 이 연구의 대상이다.

## 게이트를 만드는 방식

정책이 청크를 내놓을 때마다 게이트가 `P(quantize)` 를 하나 답한다. 그 값이 임계값
`τ` 를 넘으면 압축, 아니면 원래 속도. **우리가 추가하는 모든 모듈의 출력 타겟은
이 스칼라 하나다.**

게이트를 학습시키려면 라벨이 필요하고, 라벨은 **VLM 교사**가 만든다. 파이프라인은
네 층이다.

```
1  임베디먼트 어댑터   압축이 그 로봇에서 무엇을 뜻하는지 (아래 참고 — 여기가 갈린다)
2  결정론적 계산층     액션 숫자만으로 정확히 나오는 위험 신호
3  VLM 판단층         계산으로 알 수 없는 장면 정보만
4  집계·증류          noisy-OR 로 합치고 순위정규화한 뒤 소형 모듈로 증류
```

2 층과 3 층의 분업이 이 방법의 요점이다. **계산으로 알 수 있는 것은 VLM 에 묻지
않는다.** 물어보면 무작위 수준으로 답한다 — 방향 반전을 물었을 때 AUC 0.520 이었다.
대신 계산해서 **사실로 진술해준다.** 질문으로 주면 답이 붕괴한다 — 1,295 프레임의
답이 두 조합으로 무너진 적이 있다.

## 임베디먼트마다 압축의 뜻이 다르다

**여기를 틀리면 그 뒤가 전부 무의미하다.**

| 임베디먼트 | 액션 | 압축 |
|---|---|---|
| RoboCasa Kitchen | EE 델타 | 인접 두 스텝을 **더한다** (델타는 합성되므로) |
| allex | 절대 관절 타겟 | 타겟을 **건너뛴다** |
| dexjoco | 절대 관절 타겟 | 블록의 마지막 타겟만 남기고 **건너뛴다** |

절대 타겟을 더하면 관절 각도를 두 배로 명령하게 되어 대개 한계를 넘는다. 새 임베디먼트에
붙일 때 가장 먼저 확인할 것이 이것이고, 근거를 셋 이상 잡아두는 편이 좋다 —
dexjoco 에서는 체크포인트 메타데이터의 `"absolute": true`, 정지 루틴이 0 이 아니라 현재
자세를 재전송한다는 점, 그리고 처리 경로가 자세를 서보에 직접 넘긴다는 점을 확인했다.

기술자 임계값도 이식되지 않는다. RoboCasa 값을 dexjoco 에 그대로 썼더니 위험 플래그가
청크의 87%·95% 에서 발화했다 — 신호가 아니라 잡음이다. 실제 액션을 덤프해 다시 재는
단계가 반드시 필요하다.

## 게이트 아키텍처 — 시도한 것들

| 이름 | 무엇 | 추론 비용 | 결과 |
|---|---|---|---|
| **A′** | 독립 소형 CNN, 이미지+지시문만 | +0.6 ms | 현재 주력 |
| **B** | 정책의 VLM 특징을 빌려 쓰는 헤드 | ~0 (백본 재사용) | A′ 보다 낮았음 |
| **C** | DiT 옆의 게이트 토큰, 공동 학습 | 헤드만 | 초기 변형 |
| **DinoGate** | DINOv3 ViT-S/16 동결 + attention 풀링 | +7 ms | 폐루프 평가 대기 |
| **N1.7 공동 파인튜닝** | 백본의 다른 레이어를 읽고 함께 학습 | 헤드만 | 진행 중 |

**A′ 가 액션을 입력으로 받지 않는 것은 의도된 제약이다.** 액션 헤드의 디노이징과
동시에 실행해 지연을 숨기려는 설계이고, 액션을 받으면 순차 실행이 되어 순수 오버헤드가
된다. (다만 현재 평가 하네스에는 그 동시 실행이 아직 구현돼 있지 않다 — 지금 측정되는
게이트 비용은 전부 가산이다.)

**B 가 낮았던 이유**로 두 가지를 본다. 전체 토큰 평균 풀링이 텍스트까지 섞어 공간·객체
정보를 잃었고, 애초에 액션 예측에 맞춰진 표현을 그대로 받는다. 두 번째 천장을 걷어내려는
것이 N1.7 공동 파인튜닝이다.

## 측정으로 결론난 것 — 다시 뒤집지 말 것

| 결론 | 근거 |
|---|---|
| 액션 관련 문항은 묻지 말고 계산한다 | 물으면 AUC 0.520 (무작위) |
| 계산값은 질문이 아니라 사실로 진술 | 질문으로 주자 1,295 프레임이 2 조합으로 붕괴 |
| 스케일 기준 이미지 필수 | 그리퍼 검출 36.2% → 83.9% |
| 가중평균보다 noisy-OR | 검출률 4.5% → 71.6% |
| 가이던스만으론 부족, 문항도 국면 기준 | OpenDrawer 0% → 67% |
| 2 콜이 8 콜보다 낫다 | AUC 0.830 vs 0.763, 3.6 배 빠름 |
| 모델 크기는 지연 제약이 아니다 | 파라미터 12 배를 키워도 0.60 → 0.61 ms |
| 서로 다른 라벨로 학습한 학생의 AUC 비교는 무의미 | 증류 붕괴 감지용으로만 |

## 라벨링 세대와 집계 방식 — 용어 주의

**라벨링**과 **집계**는 다른 것이다. 혼동하기 쉽다.

- **phase5** — 국면 기준 가이던스 + 파지 유지 축 문항으로 한 VLM 라벨링. 247,887 청크.
  VLM 호출은 이것 한 번뿐이다.
- **집계 방식** — 같은 라벨을 점수로 합치는 방법. 셋으로 갈렸다.

```
phase5 · 이진        계산 플래그를 0/1 로 (원래 방식)
phase5 · 비율형      네 플래그를 전부 "해로운 병합의 비율" 로 연속화
phase5 · 사건보존형  누적형만 비율, 사건형(파지전이·방향반전)은 0.9 유지
```

이진 집계에는 결함이 있었다. 플래그 하나만 켜져도 noisy-OR 이 포화해 전체의 29.51% 가
점수 0 으로 동점이 되고, 그 구간에서 VLM 판단이 통째로 버려진다. 연속화는 재라벨링이
필요 없다 — 액션 숫자에서 다시 계산하면 되고 CPU 101 초면 끝난다.

폐루프 결과 (23 태스크 완주분):

```
              성공률   성공시 스텝   직선 대비 초과
무압축        0.657    327.0        —
무지성 K2     0.598    214.0        —
이진          0.638    274.5        +0.0078
비율형        0.635    266.6        +0.0076
사건보존형    0.627    252.0        +0.0111   ← 최고
```

성공률만 보면 사건보존형이 낮지만, **같은 스텝 수에서 단순 교환선보다 위**다.
압축은 성공률과 스텝을 맞바꾸므로 이 축으로 봐야 한다.

## 지금 열려 있는 문제

**phase5 의 D 문항이 죽어 있다.** "그리퍼가 손잡이에 닫히고 있는가" 를 묻는데 전
데이터에서 0.5 를 한 번도 안 넘었고 계산 플래그와 상관 0.75 다. 계산으로 아는 것을
물어본 것이다.

**여는 동작에 위험 신호가 없다.** 문항 넷이 전부 바닥이라 OpenDrawer 가 −0.30 으로
가장 크게 잃는다. phase6 는 이 사각지대를 메우려는 재설계이고, 축을 **"한 방향으로만
움직이는 부품을 잡고 있는가"** 로 바꾼다. 서랍을 닫는 것과 여는 것은 질량과 마찰이
같은데 하나만 압축을 견딘다 — 힘은 대칭이므로 "파지를 유지해야 하는가" 는 틀린 축이었다.

phase6 문항 다섯은 각각 하나의 축에 대응한다. 빈 공간 이동(안전) · 한 방향 부품을 잡음 ·
무게를 받거나 내려놓음 · 앞을 막는 턱이나 모서리 · 팔이 안 닿아 베이스가 함께 움직여야 함.
가이던스는 다섯 축을 각각 한 문단으로 서술한다 — 이게 중요하다. 처음에는 세 축만 서술한
가이던스로 파일럿을 돌렸고, 설명되지 않은 두 축의 문항이 죽은 것으로 나왔다. 문항이 아니라
**답할 근거를 주지 않은 것**이 원인이었다.

**문항 자격은 검증된 집합에 눈금을 맞춰 판정한다.** 기준은 "그 문항을 빼면 τ 에서 차단되는
청크 집합이 얼마나 바뀌는가" 이고, 임계값은 임의로 정하지 않는다. phase5 문항 넷에 같은
검사를 걸면 0.003 · 0.036 · 0.087 · 0.000 이 나온다 — 폐루프에서 값이 확인된 집합이므로
살아있는 문항의 실제 범위가 0.04~0.09 라는 뜻이고, 죽은 문항(q_D)은 0.000 이다. 10% 같은
숫자를 기준으로 잡으면 phase5 전체가 탈락한다.

**다만 이 수치는 구성에 따라 흔들린다.** 같은 문구가 가이던스와 슬롯 수가 바뀌자 0.189 에서
0.035 로 움직였다. 그래서 파일럿은 **명백히 죽은 문항을 거르는 필터**로만 쓰고 순위를 매기지
않는다. 같은 3,000 청크에서 phase5 와 phase6 의 차단 결정이 36% 다르므로, 가릴 것은 폐루프가
가린다.

**allex 의 τ 를 정할 수 없다.** 정책이 없어 폐루프를 돌릴 수 없다. 정성 판단용 라벨
영상까지가 산출물이다.

**DinoGate 가 프로브와 실제 학습에서 반대 결과를 냈다.** 프로브 0.829 vs 0.734 로
앞섰는데 전량 학습에서 0.639 vs 0.674 로 뒤집혔다. 폐루프가 답한다.

## 반복해서 겪은 실패 유형

**정상 종료하면서 아무 일도 하지 않는 실행.** 이 프로젝트에서 여러 번 있었다.

- 게이트 손실이 어떤 백본 파라미터에도 닿지 않은 학습 — `hidden_states[k]` 가 k 번째
  레이어의 **출력**이라 탭이 k−1 아래로만 그래디언트를 보내는데, 탭을 동결 구간에
  두었다. 손실은 정상적으로 내려가고 게이트 헤드도 학습된다.
- 어레이 인덱스가 범위를 벗어나 태스크가 하나도 선택되지 않은 평가 — 서버는 뜨고
  로그에 `done` 이 찍힌다.
- 상위층 unfreeze 를 게이트 분기 안에 두어 베이스라인만 백본이 동결된 채 학습된 대조군.
- 배포된 체크포인트 config 가 백본 전체를 학습 대상으로 만들어, 의도와 다르게 1.5B 를
  파인튜닝하려 한 설정.

**그래서 판정은 항상 산출물로 한다.** 잡 상태나 로그가 아니라, 에피소드 줄이 쌓였는지,
체크포인트에 게이트 텐서가 들어갔는지, 어느 파라미터가 그래디언트를 받았는지를 센다.

**환경을 올려서 고치지 않는다.** RoboCasa 가 numpy 1.23.x 를 요구하고, 그것을 올렸다가
평가가 열흘 죽었다 — 그때 증상은 numpy 와 무관해 보였다(프로세서 설정 누락, npz 가
numpy2 pickle 로 저장됨). 더 최신 라이브러리가 필요하면 **그 프로세스의 PYTHONPATH 에만**
얹는다.

**보관 정책으로 데이터가 사라진다.** 읽기만으로는 보호되지 않는다. 37GB 프레임 캐시가
그렇게 없어졌고, dexjoco 학습에 쓴 변환 데이터셋도 사라졌다. 계속 쓰는 자산은 홈에 두고
나머지는 재생성 가능하다고 가정한다.

포함돼 있어 클론 하나로 학습이 된다.
